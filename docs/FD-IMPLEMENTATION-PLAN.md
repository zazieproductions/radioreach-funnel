## Architecture

Cloudflare-native, free-tier compatible. No new external services.

1. **Persistence — Cloudflare D1** (`radioreach-course`, binding `DB`).
   Normalized schema in `migrations/0001_fd_schema.sql`; course content and the
   proprietary 300-station database are generated by `scripts/build-fd-content.mjs`
   into `migrations/0002_fd_seed_content.sql` (idempotent upserts — content updates
   never touch progress/notes rows). Ownership (`user_id`), timestamps, FKs, indexes.
2. **Content pipeline** — `scripts/build-fd-content.mjs` parses the master package:
   lesson MD → structured block JSON (mission brief, masterclass, field protocol,
   worked example, warnings, decoder notes, exercises + machine-checkable pass
   standards, drills), 21-day calendar → task templates, heat-map DB → station rows,
   insider decoder → per-lesson tooltips, playbooks/vaults → native tool data.
   Outputs `src/fd/data/generated/*` (client outline only: titles/meta) + full lesson
   bodies land in D1 (gated API).
3. **API — Pages Functions**:
   - `functions/api/fd/auth/*` register / login / logout / session / claim-purchase
     (PBKDF2-SHA256 210k iters via WebCrypto, server-side session rows, HttpOnly
     Secure SameSite=Lax cookies, double-submit CSRF header, KV rate limiting).
   - `functions/api/fd/[[route]].ts` — dispatcher for all data routes; every handler
     runs `requireUser` → `requireEnrolled` → ownership-scoped SQL. Stations are
     served paginated + filtered; there is no full-dump endpoint.
   - `functions/api/stripe/webhook.ts` — extended (not replaced): existing order +
     Meta CAPI flow preserved; adds durable `webhook_events` idempotency, entitlement
     grant on paid sessions containing `frequency_dominion`, refund → revoke,
     dispute created/closed handling. Client can never set entitlement.
4. **Entitlement model** — `entitlements` keyed by (user_id | normalized email),
   states `active | pending_link | refunded | disputed | revoked`; sources
   `stripe | claim | admin`. Post-purchase flow: paid checkout → success page offers
   account creation; email-normalized webhook grants auto-link.
5. **Client** — second Vite entry `fd.html` mounted by `src/fd/main.tsx`, real paths:
   `/frequency-dominion` (static sales page, copy corrected), `/frequency-dominion/login`,
   `/signup`, `/app` dashboard, `/app/module/:id`, `/app/lesson/:id`, `/app/campaign`,
   `/app/heatmap`, `/app/stations`, `/app/notes`, `/app/analytics`, `/app/vault`,
   `/admin`. Served via `public/_redirects` (`200` rewrites) in prod, vite middleware in dev.
6. **Maps** — dependency-free SVG workspace: Albers-projected station/choropleth views
   (density, rings, tour corridor, outcomes, format heat), wheel/drag/keyboard zoom +
   pan, grid clustering, animated transitions (reduced-motion aware), color-safe
   palette, legend + accessible table twin, tile-provider-independent by design
   (config seam left for future raster basemap).
7. **Local dev** — `scripts/fd-dev-api.mjs` (vite plugin) runs the real handler code
   against `node:sqlite` D1 shim + KV shim with auto-seed, so `/api/fd/*` works with
   plain `npm run dev`; production runs the same handlers against D1 via `DB` binding.
8. **Tests** — `scripts/fd-tests/*` (node:test + tsx): authz, webhook signature +
   idempotency + refund, enrollment/claim, progress gating + persistence, notes
   autosave, campaign wizard determinism, scoring math, follow-up auto-cancel,
   analytics denominators, user isolation, admin-only routes, sanitization; jsdom UI
   tests for nav/responsive + lesson flow.

## Security invariants

- Authorization is only ever evaluated server-side; localStorage is cache, not proof.
- Stripe secrets stay in Pages Function env (`STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`).
- All user-authored text stored raw-Markdown but rendered through a safe subset
  renderer (HTML escaped; no `dangerouslySetInnerHTML`); URL fields validated https/http.
- Every query filters by `user_id`; admin endpoints require `role=admin`.
- Webhook processing idempotent (event id unique key) and signature-verified.
